# pdf-extract 工作流与排错参考

## 0. 时间预算与停止规则

| 环节 | 预算 | 到点动作 |
|---|---|---|
| info | <2 s | — |
| 扫描件提取 | 4–5 s/页 | 超过 2× 先检查 dpi/页数，别盲目重跑 |
| compare | ≤5 s | 参数错，看「诊断与下一步」 |
| 差异裁图 | ≤5 张、≤60 s | 只裁真实差异 |
| 报告 | 1 份 md | 一次写完 |
| **工具步骤** | **≤8 次** | 用 `qc` 合并 info+extract+compare |
| **单次核对任务总计** | **10 min（24 页目标 ≤3 min）** | 必须收尾：给已确认结论 + 未确认项 |

规则：同一动作最多重试 1 次；某步超 2× 预算 → 换方法，不加大验证。
**注意：模型自身每步约 19 s（TTFT 为主），34 步就能吃掉 10 分钟。步骤数比工具耗时更值得砍。**

## 1. 决策树

```
任务开始
├─ 提取/转换类（转 Word/Excel/Markdown/CSV）
│  └─ extract/convert → 交付 + 说明局限 → 询问是否需要核验（≤3 min）
└─ 读取/核对类（对不对 / 和 Excel 比）
   ├─ 1. qc <pdf> <基准> -o <out>        ← 一条命令：info+提取+自动映射+比较
   │     ├─ 看 stdout：行数、rate、real_diffs、hints
   │     ├─ 提示"行数 ≈ 基准×2" → qc --max-pages <单份页数>（复用提取，重新 OCR 该范围）
   │     └─ 提示"匹配列 <4" → 退回 compare 手工 --base-cols/--got-cols
   ├─ 2. 只对 real_diffs 的"数值不同/不一致"裁图（≤5 张）
   └─ 3. 写 1 份报告（真实差异 / 已知噪声 / 无法比对）
```

## 2. 不同文档的参数建议

| 文档情况 | 建议 |
|---|---|
| 双面扫描、奇偶页方向相反 | 默认即可（逐页判断方向） |
| 页面 90° 侧躺表格 | 默认即可 |
| 原生只有 150dpi、字很小 | `--dpi 300` 放大再 OCR（会变慢） |
| 彩色底/水印重 | 先 `--max-pages 2` 试；必要时预处理图片 |
| 无框线表格 | 自动退化为"文本行聚类"，优先用 md/txt |
| 多栏文章/杂志 | 表格重建未必触发；md 按 XY-cut 阅读顺序输出 |
| **同表重复打印/多份装订** | `info` 后按页数拆份，`--max-pages <单份页数>` 只抽一份 |
| 上千页 | 分批 `--max-pages` 或先拆 PDF |

## 3. 输出质量自检（读取/核对任务，≤1 分钟）

1. `run_report.json` 的 `warnings`：方向存疑的页才抽查。
2. `<stem>.md` 前 2 页：表头、每行列数是否对齐。
3. `tables.json`：每页 `tables[0]` 列数是否稳定（应等于真实列数）。
4. 只在 `compare` 报出真实差异后才打开 `pages/page-XX.png` 裁切目视，**总数 ≤5 张**。

## 4. 比对策略（PDF vs Excel/CSV）

**默认走 `qc`；`compare` 只在 qc 自动映射失败或需要精确列控制时用。**

### 4.1 qc（推荐，一条命令）

```powershell
& $PY "scripts\pdf.py" qc "<pdf>" "<基准.xlsx>" -o "<out>"
& $PY "scripts\pdf.py" qc "<pdf>" "<基准.xlsx>" -o "<out>" --max-pages 12   # 只取一份打印
```

输出 JSON 关键字段：`rows`（基准/PDF 行数）、`rate`、`verdicts`、`real_diffs`、`noise_counts`、`mapping`（识别到的列与表头行）、`hints`、`timing_s`。

判读顺序：

1. `rows.pdf ≈ rows.base × 2` → 重复打印，加 `--max-pages <单份页数>` 重跑（二次调用复用提取，2 s 内出结果的前提是同一 `-o` 目录）。
2. `mapping.columns` 是否与预期列一致；`hints` 里"未匹配的基准列"就是无法比对的列。
3. `real_diffs` 里的"数值不同"才是金额类真实差异；"不一致"先判断是否 OCR 串列；"整行多余"在重复打印未排除前不算差异。
4. 其余走 `noise_counts` 归类，不逐格看。

### 4.2 compare（手工，qc 映射失败时）

**固定顺序，最多 1 轮参数调整：**

1. **先看行数倍数。** `提取行数 ≈ 基准行数 × k`（k=2/3）→ 同表重复打印，`--max-pages` 只取一份再比，别逐行对齐。
2. **再对齐行。** 行数不一致 → `--base-skip` / `--got-skip` / `--base-stop-total`。
3. **再对齐列。** 列数不一致 → `--base-cols` / `--got-cols`。
4. **合并列单独处理。** 序号/单位名称/部门 → `--seq-cols` 按值序列比；基准侧可 `--base-fill-cols`。
5. **判读，不再加验证。** 按 SKILL.md 的"差异分级"一次归类；数值差异才裁图（≤5 张）。

**常见噪声（直接归类，不裁图）：**

| 现象 | 结论 |
|---|---|
| 文本"截断" | PDF 打印裁切，源问题 |
| 单格"缺失/多余" | 合并单元格落行、备注垂直居中 |
| "在租"混进使用人 | OCR 串列，合并格导致 |
| `0` vs 空 vs `0.00` | 显示差异，数值相同 |
| 千分位逗号、全半角括号 | `norm()` 已归一，不应报差异；报了就是列错位 |

**报告模板（1 份 md，别写长）：**

```markdown
# <文档> 差异核对
- 来源：PDF（N 页，扫描件）｜基准：<xlsx>（M 行）
- 提取：<耗时>；比对：<一致率>

## 结论
<一句话：是否有真实差异，几处>

## 真实差异（逐条：位置 / PDF / Excel / 判断）
## 已知噪声（类别 + 计数，不逐条展开）
## 无法比对（PDF 未打印的列、裁切内容）
## 建议
```

## 5. 常见故障

| 现象 | 原因 / 处理 |
|---|---|
| doctor 报缺包且安装失败 | 离线：`--python` 指向已有依赖的解释器；或设 `PIP_INDEX_URL` 后重跑 |
| 安装到一半失败 | 删除固定目录 `%USERPROFILE%\.dsh\pdfskill` 重来（pip 缓存也在里面） |
| 所有页 OCR 都乱 | 方向判断失败：删输出目录 `pages/orientation.json` 或加 `--recheck-orient`；仍不对就先手动旋转另存再跑 |
| 表格列数比真实少/多 | 框线检测受扫描质量影响；加 `--dpi 300`，或用 md/txt 后处理 |
| 某几页表格串行 | 该页可能无框线或斜扫描；看原图，必要时单页人工核对 |
| compare 大量"整行多余/缺失" | 重复打印或表头/页脚未跳过；不要写脚本，用 `--max-pages`/`--got-skip` |
| compare 一致率 <70% | 行/列错位；按提示调参数 1 轮，仍不行隔离单份重跑 |
| 加密 PDF | 本工具不解密，先解密 |
| 输出 docx 打开异常 | 极少见；先用 xlsx/md，或去掉异常页重导 |

## 6. 目录约定

- 运行环境（固定）：`%USERPROFILE%\.dsh\pdfskill`（venv、pip 缓存、env.json）——可用 `PDFSKILL_HOME` 改；换工作目录不用重装。
- 提取产物：`-o` 指定目录（默认 `<PDF名字>_extract/`），含 `pages/` 渲染图与 `run_report.json`。
- 交付目录只放：报告 md（必要时差异 xlsx）。中间脚本、裁图用完删。
- 本仓库：根目录含 `SKILL.md` + `scripts/` + `references/`。

## 7. 当前性能基线（8C16T，无 GPU）

| 场景 | 耗时 |
|---|---|
| 11 页扫描件 200dpi 首次 | ≈50 s |
| 24 页扫描件 200dpi 首次 | ≈100 s |
| 同一 PDF 再次（方向缓存） | ≈45 s |
| 文本层 PDF | <1 s |
| 单页扫描件 | 4–5 s |
| compare（120 行×10 列） | ≈1.5 s |
| **24 页核对全流程（单份）** | **≈70 s** |
| qc 单份（12 页，含提取+映射+比对） | ≈68 s |
| qc 二次调用（复用提取结果） | ≈2 s |
| qc 全本 24 页（两份打印） | ≈127 s |

方向判定：先长直线形态定 0/90，再用墨迹投影找 3-4 条文本行、各裁 320px 小段只做识别，比较正/倒得分。比"整页检测 + 多框识别"快约 3 倍，结果一致。

## 8. 事故复盘

### 8.1 为什么会拖到 55 分钟

- 输入：24 页扫描件（同一张表两份打印）+ Excel 基准。
- 实际耗时：OCR 96 s；其余 ~48 min 全部是**自建 6 个对齐脚本 + 30 余张裁图目视 + 独立复核 + 写长报告**。
- 根因：没有先识别"重复打印"，绕开内置 compare 自建对齐；为单条结论做了全量二次证明。
- 按本文件流程重跑（`--max-pages 11` + 一次 `compare` + 判读）：**70 s**，结论相同。
- 固化措施：SKILL.md 第 0 节的时间预算与反模式；`compare` 输出新增「诊断与下一步」（行数倍数、低一致率、真实差异数、时间提醒）。

### 8.2 为什么加了规则后仍是 12 分钟（34 步复盘）

同一任务第二次实测 **12 分 06 秒**。拆开看：

| 项 | 数值 | 说明 |
|---|---|---|
| 工具调用计账 | **89 s** | 后台跑了两轮提取：全本 24 页 98 s + 首份 ~66 s（**重复提取**），与模型时间重叠 |
| 模型推理 | **636 s（10:36）** | 34 步 × 平均 ≈19 s（TTFT ≈14 s/步） |
| 步数 | **34 步 / 38 次调用** | 含 1 次 spawn 子 agent + 1 次 wait（≈65 s 纯等待） |

主要浪费点与整改：

1. **spawn 子 agent 去 profile Excel** → 删掉；`qc` 用表头文字自动映射列。
2. **先全量提取、再发现重复打印、再提取一份** → `qc` 直接提示"行数 ×2，用 `--max-pages N`"，二次调用复用提取。
3. **手工读 CSV/TSV/表结构 8 步** → `qc` 输出 `mapping` + `real_diffs`，一次到结论。
4. **报告 write 之后又 edit** → 一次写完整报告。
5. 结论：**工具已经够快，剩下的优化是"少调用几次模型"**——目标 ≤8 步。

### 8.3 目标流程（3–5 步）

```
skill 加载 → qc（必要时 + --max-pages）→ 裁 ≤5 张差异图 → 写 1 份报告 → 交付
```

预期 24 页核对：**≈2.5–3.5 分钟**（提取 68–127 s + 模型 4-5 步）。
